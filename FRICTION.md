# Friction log

Every surprise we hit while building Go Figure with Symfony AI and the PHP MCP SDK, one line each.
The ones worth reporting become issues or pull requests, tracked in [UPSTREAM.md](UPSTREAM.md).

| Date | What we were doing | What happened | What we expected | Follow-up |
| --- | --- | --- | --- | --- |
| 2026-11-09 | First HTTP request to the MCP endpoint right after `composer require symfony/mcp-bundle` (1.0.0-BETA1) | HTTP 500: `No PSR-17 server request factory found`; nothing had installed a PSR-7/PSR-17 implementation | A working endpoint, as the recipe announces | Already fixed on `main` by symfony/ai#2828 (merged after BETA1). Workaround: `composer require nyholm/psr7`. |
| 2026-11-09 | Declaring the MCP server under the key `go-figure` in `config/packages/mcp.yaml` | The server advertised itself as `go_figure` in `initialize`: Symfony Config turns dashes into underscores in the key, and the name defaults to the key | The name we typed | Set `name` and `http.path` explicitly. A pull request by a maintainer keeps the hyphens: symfony/ai#2834 (open on Nov 17, milestone v1.0). |
| 2026-11-09 | Generating the layout schema (`ResponseFormatFactory::create(Page::class)`) inside the app, then with `new ResponseFormatFactory()` in a plain script | Not the same schema: through the bundle, every `DiscriminatorMap` union gets `"type": "object"` next to its `anyOf`; standalone, it does not. The bundle registers the describers in a different order from the `Describer` default (`TypeInfoDescriber` runs before `SerializerDescriber`) | One schema for one class | To check on `main`, and against providers when we submit the schema. We always build it from the container, and a test compares it with the MCP constant. |
| 2026-11-09 | Using a class from a `DiscriminatorMap` directly as a property type (`list<Measured>` for the operands of an operation) | Its discriminator property is a bare `string` in the schema: the `enum` is only added when the class is reached through the map | The model told which value to write | Workaround: `#[Schema(enum: ['measured'])]` on the property. Nothing to report. |
| 2026-11-10 | Adding `symfony/validator` to check the layout a model writes (no digit in free text) | Symfony AI then validates the final structured output with the default group and throws `ValidationException` on the first violation (streamed partial snapshots are not validated). Its schema describer also turns built-in constraints (`Regex`, `Length`…) into JSON Schema keywords | To decide ourselves what a violation does: here, mark one note "unsourced" and keep the rest of the page | Our rules are custom constraints in their own `render` group, so neither the schema nor the platform's check changes. Nothing to report. |
| 2026-11-12 | Streaming a page with `response_format` and `stream: true` (`PartialObjectStreamListener`), with a scripted model cutting the JSON anywhere | A partial object can hold a string cut mid-token and still denormalize: the last component of a partial page may name the period `20` while the model is writing `2024`. Rendering it then showed a refusal for a cell the model never asked for | A way to tell which parts of a partial object are finished | The n−1 rule: a component is used only once the next one has started, and the last one when the stream ends (`App\Ai\PageStream`). To check whether the docs warn about it. |
| 2026-11-12 | Looking for the layouts a model got wrong, in the server logs | The SDK checks the tool arguments against the input schema and answers `-32602` with the validation errors. Its log holds the arguments it received (`Executing tool`, debug level), but no line for the refusal, unlike a tool that throws (`Unhandled error during tool execution`) | A log entry for the refused call | The SDK dispatches `Mcp\Event\ErrorEvent` through Symfony's event dispatcher: a listener logs the refusal (`App\Mcp\RefusedCallLog`). Nothing to report. |
| 2026-11-13 | Showing the schema errors of a hand-edited layout on "Try to make it lie", with the SDK's own `SchemaValidator`, then calling `render_page` over HTTP with a note whose segment has an unknown `kind` | Our layout is a union (`anyOf`) of five components. The validator lists the leaf errors of every branch, and the tool error keeps the first three: the model reads that its note misses `label` and `title` (the properties of a tile and a chart), then `...and more errors`. The error about the segment is only in `data.validation_errors` (7 errors) | The error of the branch the call meant (its `kind` matched), first | On the page, we sort the errors deepest first. Reproduced with a four-branch `anyOf` on `mcp/sdk` 0.9.0. To check on `main`, then report. |
| 2026-11-17 | Turning on the Symfony profiler, to show the Symfony AI panel for `/ask` | With the profiler, `TraceablePlatform` wraps the streamed result; `asObject()` then fails once the stream is read, and `/ask` showed "The model wrote no page." | The same result with and without the profiler | Already fixed on `main` by symfony/ai#2843 (merged on Oct 27, after 1.0.0-BETA1). Workaround: the platform of `/ask` is not traced; the HTTP Client panel shows the call. |
| 2026-11-17 | Replaying the example questions of `/ask` without a key | `Test\Replay\CassetteHttpClient` replays a recorded stream through the real Hugging Face bridge, its parser and the structured output; recording a hand-written answer only needs a `MockHttpClient` as the "real" client. It checks that the request matches the recording | — | Nothing to report: we use it outside tests on purpose, with one fresh cassette per request (`App\Ai\Cassettes`). |
| 2026-11-19 | First live question with an Anthropic key (`claude-haiku-4-5`), `response_format: Page::class` | HTTP 400 `For 'anyOf', 'type' is not supported`: the schema factory writes a union of objects as `{"type": "object", "anyOf": [...]}`, and the Anthropic bridge sends it as it is | A schema the provider accepts, as the bridge already rewrites other keywords (`JsonSchemaSanitizerTrait`) | To report, after checking it is not known. Workaround: `App\Ai\AnthropicSchemaListener` drops the `type` next to an `anyOf`, for Claude models. |
| 2026-11-19 | The same question, once the schema was accepted | HTTP 400 `The compiled grammar is too large`: the factory writes a class in full at every place it is used (a figure appears in five components), with no `$defs` | — (a limit of the provider, met with a 9 kB schema) | Workaround in the same listener: a figure is defined once in `$defs` and referenced; Anthropic then accepts the schema. |
| 2026-11-19 | The import agent with an Anthropic key, `response_format: Proposal::class` | HTTP 400 `Invalid JSON Schema in output format: None is not of type 'string'`: an `Assert\Regex` whose pattern has no HTML form gives `"pattern": null` in the schema (`ValidatorConstraintsDescriber`, `getHtmlPattern()`) | No `pattern` keyword when there is no pattern | To report, after checking it is not known. Workaround in the same listener: keywords without a value are dropped. |
